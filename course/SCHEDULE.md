# Teaching cadence and schedule

The learner chooses the schedule: weekly hours, the core/exploration split, and project start and finish dates. The [charter](CHARTER.md#workload) owns this policy. This file turns a chosen pace into a plan and forecast. Live dates and progress belong to the learner's private progress tracker.

## Choosing a weekly pace

Pick the hours you can sustain. The instructor fits lessons into that time; a lighter week just moves the forecast. As a default, split each week's study time roughly like this:

| Activity | Share of study time | Purpose |
|---|---:|---|
| Building, running and debugging | ~75% | Develop the current artifact, with explanations as needed |
| Targeted explanation or reference lookup | ~10% | Resolve gaps found while building; unused time returns to building |
| Practical review and transfer | ~15% | Inspect results, repair a failure or modify working code |
| Exploration (optional) | any | Investigate a placed idea; take it from the week's time or add it |

At 8 hours/week that is about 6 building, 1 explanation and 1 review. Setup, explanations, building and review all count; count each minute once.

## Planning and review

1. Inspect current code and existing evidence to choose the next useful component within one bounded project. Learn prerequisites through small implementation attempts.
2. Prepare its workshop contract, code scaffold, observable checks and resource limits; select references only for the current need. Size the deliverable, feedback and revision to finish in about three weeks at the learner's pace.
3. Ask the learner for the start and target finish, keep one active project at a time, and record it in the learner's tracker.
4. During each study week, review the attempt, record actual hours/assistance, and place new ideas. The instructor may rearrange equivalent work within the learner's chosen time and report the change.
5. At the target finish, assess the evidence and update the forecast. A `revise` result calls for targeted remediation and a fresh variation before dependent work. If more time is needed, propose a revised scope or date; the learner decides.

Long-range sequence follows the roadmap; only the active project receives lesson-level commitments. An unfinished deliverable is split or reduced rather than stretched indefinitely.

## Duration forecast

The roadmap estimates 233–391 focused core hours before diagnostic credit or extra remediation. Duration is total hours divided by your weekly pace:

| Core hours/week | Arithmetic duration |
|---:|---|
| 5 | About 47–79 weeks |
| 8 | About 30–49 weeks |
| 10 | About 24–40 weeks |
| 15 | About 16–27 weeks |

These are arithmetic, not promised completion dates. Count a substituted exercise once. Remediation, holidays and hardware delays lengthen the course; verified prior knowledge shortens it. Reforecast from actual hours after the first completed project.
